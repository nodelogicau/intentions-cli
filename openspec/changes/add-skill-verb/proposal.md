## Why

A harness that drives `intentions` needs to know the verbs, the list-before-add loop, and the rules that keep it on its side of the line: draft tentative, never invent a slot, never firm without a policy. particulars-cli solved this by embedding its skill in the binary, stamped with the binary's version so skill and verbs cannot drift, and installing it where each harness reads it. This change gives `intentions` the same, as the third of the sibling pieces after the installer and the cask.

## What Changes

- New `skills/intentions/SKILL.md`, the canonical agent-facing skill for this format: the loop, setup, a verb table, rules for intentions and availability, retirement, git workflow, and an example session.
- New `intentions skill show [--harness <preset>]` and `intentions skill install [--harness <preset>]... [--user | --dir <path>] [--file <path>] [--force] [--check]`, ported from particulars-cli with identical semantics: version stamping, an ownership marker, five harness presets, never overwriting a foreign file, a bounded section for `AGENTS.md`, and `--check` for CI.
- The repository commits its own installed copy at `.claude/skills/intentions/SKILL.md`, regenerated by `make skill` with a `dev` stamp, and CI verifies it with `skill install --check`.
- README gains an Agent skill section; CHANGELOG records 0.3.0.
